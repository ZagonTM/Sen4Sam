## 3. Interpretation
- Baseline is poor everywhere: mean best IoU 0.085 (ES) vs 0.220 (FR); ES is clearly worse. Fields with IoU>0.5: 7.0% (ES) vs 20.6% (FR).
- At pps=16 only 32.3% of parcels receive any grid point (ES 24.0%, FR 39.6%); for parcels <100 px it is 5.8% / 13.0%. So most small fields cannot be segmented by this prompt grid regardless of the decoder: an upper bound on recall from the prompt, before any model quality enters.
- Raising pps to 32 / 64 raises that coverage to 67.9% / 94.7%. This is a measurement of coverage, not of IoU; whether SAM then produces good masks at those points is untested here.
- ES parcels are smaller than FR ones (see the per-country size table), which is consistent with part of the ES/FR gap. Hypothesis: size and prompt density explain a large share of the gap, but other shifts (crop types, texture, tile radiometry) are not separated by this analysis; the per-patch correlations above are only suggestive and confounded.
- Fine-tuning made the automatic pipeline worse on test: mean best IoU 0.156 -> 0.064 (128/132 patches worse, CI excludes zero). This is a negative result for the Phase B intervention as run.
- The fine-tuned model produces fewer masks (78.7 -> 41.1 per patch) while mask-on-field is about unchanged (0.583 -> 0.591). Hypothesis (not verified here): the IoU/stability filters discard masks, i.e. recall collapses; a filters-off evaluation would test it.
- Even a perfect decoder is capped by prompt coverage; the decoder-only adaptation attacks the wrong bottleneck for small fields. This is an argument from the coverage numbers, to be confirmed with a pps sweep run on the model.
- Limitations: per-patch aggregation hides per-field behaviour; coverage counts a point inside the parcel, not whether SAM returns the parcel mask; test split has 22 patches per tile, so tile-level numbers are noisy.
